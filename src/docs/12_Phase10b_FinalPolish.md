## 1. إعدادات البريد بإيميل المالك
- قسم `Smtp` في **كلا** appsettings معبأ نهائياً: `Host=smtp.gmail.com`، `Port=587`، `EnableSsl=true`، `User=From=hm.alkasem@gmail.com`.
- **المتبقي على المالك فقط:** حقل `Password` — يحتاج **Gmail App Password** (حساب غوغل → الأمان → التحقق بخطوتين → App passwords → أنشئ لـ Mail → 16 حرفاً).
- حارس `SmtpEmailSender` صار يتخطى الإرسال إذا `Host` **أو** `Password` فارغ (سابقاً Host فقط) — حتى لا يحاول ويفشل قبل وضع كلمة السر. مُتحقق: تسجيل حساب مع الإعدادات الحالية → سطر "skipped email" باللوغ والتسجيل سليم.

## 2. الكرت كله قابل للنقر (جامعات + سكن)
نمط **Stretched Link** خالص بالـ CSS: رابط الاسم يمتد `::after` بـ `inset: 0; z-index: 1` فوق الكرت كله، والعناصر التفاعلية (زر القلب، "قدّم الآن"، زر +، شارة السعر) فوقه بـ `z-index: 2` فتبقى بوظائفها. أينما ضغط الزائر → صفحة التفاصيل. بلا JS إطلاقاً.
الملفات: `css/components/university-card.css` + `css/pages/housings.css`.

## 3. إصلاح تناسق الفوتر بالـ RTL
**المشكلة (سكرين شوت المالك):** الهاتف والإيميل بعمود "تواصل معنا" منحازان لليسار بينما العمود يميني — لأن `dir="ltr"` كان على `<li>`/`<a>` كاملاً فعكس اصطفاف الـ flex.
**الحل:** السطر يتبع اتجاه الصفحة، وفقط النص الداخلي ملفوف `<span dir="ltr">` (الرقم/الإيميل يظلان مقروءين LTR). طُبق على الفوتر **والتوبار**.
> **قاعدة عامة استُخلصت:** لا تضع `dir="ltr"` على عنصر التخطيط (li/a بمحتوى flex) — بل على span النص فقط.

## 4. إزالة الفراغ أسفل الفوتر
`wwwroot/css/site.css` كان يحمل بقايا قالب البداية: `body { margin-bottom: 60px }` → شريط كريمي فارغ تحت الفوتر. أزيل (`margin: 0`)، وبالمرور استُبدلت حلقة الفوكس الزرقاء الافتراضية بذهبية على الهوية (`rgba(242,165,26,.55)`).

  **اختبار فعلي:** زُرعت 6 آراء مؤقتة SQL → الصفحتان عرضتا 9 كروت بسحب سليم → نُظفت البيانات المؤقتة.
